# stock-scraper-python

用 yfinance 擷取觀察名單的日行情，經 Pandas 清理後寫入 PostgreSQL（Neon），並計算技術指標、掃描選股策略。
資料表 `stocks`、`stock_prices`、`stock_actions`、`stock_indicators`、`strategy_signals` 由本專案建立與維護，Java API 只讀取。

## 安裝（建議 Python 3.12，最低 3.11）

```bash
cd stock-scraper-python
python3.12 -m venv venv
source venv/bin/activate          # Windows：venv\Scripts\activate
pip install -r requirements.txt
```

## 設定資料庫連線

```bash
cp .env.example .env              # 再填入實際的 DB_URL / DB_USERNAME / DB_PASSWORD
```

- `DB_URL` 可直接使用與 Java 相同的 JDBC 格式：`jdbc:postgresql://<host>:5432/<db>?sslmode=require`
- 帳密不要寫在 URL 中；`.env` 已被 `.gitignore` 排除
- 系統環境變數優先於 `.env`

## 執行

```bash
python -m scraper.main                 # 增量抓日 K（OHLCV），並計算技術指標、掃描策略
python -m scraper.main --full          # 強制重抓 2015-06-01 起的完整歷史（平常不需要）
python -m scraper.health               # 資料健康檢查（唯讀），見「驗證」
```

**觀察名單**：在 `scraper/config.py` 的 `STOCK_GROUPS` 分組設定（上市代號加 `.TW`、上櫃加 `.TWO`），`WATCHLIST` 為全部組別的聯集。
目前有 `TW50`（0050 成分股，2026-10-30 元大投信公布的持股，50 檔）與 `CUSTOM`（自選，16 檔），同一檔可同時屬於兩組，合計 58 檔。
組別寫入 `stocks.group_codes`；從設定移除的股票保留歷史資料，但清除組別。0050 每季調整成分股，需手動更新名單。

**庫存中的股票**：從觀察名單移除但仍有人持有的股票，每日照常更新日 K、指標與參考價位（`config.tracked_stocks`），
庫存頁的價格與停利線才不會停在移除那天；只讀 `holdings` 的股票代號，不讀使用者與買進內容。
回測、投資組合回測與交易計畫仍只使用觀察名單。

**上市日期**：Yahoo 的日 K 可能包含上市前的興櫃期間（沒有漲跌幅限制），或合併改制前另一家公司的價格。
每次執行會從證交所 / 櫃買中心的公司基本資料（開放資料）取得上市 / 上櫃日期（`scraper/listing.py`，存在 `stocks.listed_date`），
只保留該日起的資料；無法連線時沿用資料庫中的紀錄。2026-10-30 因此排除了日月光投控、緯穎、力積電、藥華藥、鴻勁上市前的資料。

**增量抓取**：資料存在自己的資料庫，每次只從資料庫最新的日期接著抓，並往前重疊 10 個交易日（`config.OVERLAP_TRADING_DAYS`），
用來接收 Yahoo 對最近幾天的修正，以及偵測下面的價格重新調整。電腦關機多久，下次執行就從那裡接著補。

**完整歷史（回測用）**：資料庫保存 2015-06-01（`config.HISTORY_START`，台股漲跌幅自這天起放寬為 10%）起的日 K。
以下情況會自動改抓完整歷史，不需要手動處理：

- 資料庫還沒有這檔股票的完整歷史（例如第一次執行，或新加入觀察名單）
- Yahoo 因配股、減資、分割重新調整了歷史價格：比對重疊日期的收盤價，整體差超過 0.1% 就重抓
  （Yahoo 不一定會記錄分割事件，例如 0050 的 1 拆 4，所以用價格比對而不是看事件紀錄）

除權息與股本事件（現金股利、配股 / 減資 / 分割比例）存在 `stock_actions`，回測時用來計算含股利的還原報酬，
庫存（Java）用分割比例把買進時的股數換算成現在的股數。
Yahoo 漏掉的股數變動（價格已換算、卻沒有事件紀錄）查證後列在 `scraper/corrections.py`，每次更新時補進 `stock_actions`；
目前只有 0050 的 1 拆 4（2025-06-18）。Yahoo 日後補上同一事件（前後 30 天內有其他股數變動）時會略過並在 log 提醒移除。
`verify.sql` 查詢 27 會列出停牌卻沒有股數變動紀錄的期間，可用來找漏掉的事件。
注意：最近一次配股或減資**之前**的價格是 Yahoo 換算後的數值，與當年的實際報價不同（例如鴻海 2018 年減資前的價格 ÷ 0.8），
報酬率不受影響。

清理規則（不寫入資料庫，並在 log 中列出日期）：

- 收盤價為空的資料
- 休市日補值：成交量 0 且開高低收相同（資料庫中已存在的也會刪除）
- 開高低收不合理：最高價低於開盤 / 收盤，或最低價高於開盤 / 收盤

價格未還原除息（與券商報價一致），除息日的 K 線會出現跳空缺口；股票分割則由 Yahoo 調整過，分割前後的價格可連續比較（例如 0050 於 2025 年 6 月分割）。

| exit code | 意義 |
|---|---|
| 0 | 全部成功 |
| 1 | 部分股票擷取或寫入失敗（其餘仍會寫入） |
| 2 | 環境變數缺漏或格式錯誤 |
| 3 | 資料庫連線失敗，或既有資料表結構不符 |

`run_daily.sh`（一鍵更新、每日排程）另有 4：更新成功，但資料健康檢查發現異常或無法執行（macOS 通知標題為「股票資料檢查有異常」）。

可重複執行：同一股票、同一交易日只會有一筆；數值沒變就不更新。

## 驗證

在 Neon Console 的 SQL Editor 貼上 `sql/verify.sql` 執行，或使用 psql：

```bash
psql "host=<host> dbname=<db> user=<user> sslmode=require" -f sql/verify.sql
```

查詢 4、6、7、11、12 應回傳 0 列（12 不含每檔前 120 筆的指標暖身期）；查詢 8（缺漏交易日）有已知例外，列在查詢的註解中；查詢 9 的兩個筆數應相同；查詢 16～20 為官方開放資料的累積狀況、事件日偵測、收盤價比對、除權除息預告與資料庫用量；查詢 21～23 為完整歷史的涵蓋範圍、除權息事件與單日漲跌異常（23 有一個已知例外）；查詢 24、25 以 SQL 獨立驗算回測交易（持有 N 日），應回傳 0 列；查詢 26 以 SQL 獨立驗算參考價位，應回傳 0 列；查詢 27 檢查停牌期間是否都有股數變動紀錄，應回傳 0 列。

**每日資料健康檢查**（`python -m scraper.health`，每日更新的第 3 步）：以唯讀連線執行上面與資料來源有關、執行快速的檢查，
加上「yfinance 最新交易日是否落後當天的官方資料」與「觀察名單或庫存中的股票是否缺少最新交易日」，
異常時在 log 列出前 5 筆並以 exit code 1 結束。共 10 項：

| 檢查 | 對應 |
|---|---|
| yfinance 最新交易日落後官方資料 | 新增 |
| 股票缺少市場最新交易日（停牌時屬正常） | 新增 |
| 休市日補值、開高低收不合理、指標與日 K 筆數不一致、RSI / KD 超出範圍、暖身期之後仍為 NULL 的指標 | 查詢 6、7、9、11、12 |
| 單日漲跌超過 10%（已知例外寫在 `scraper/health.py`） | 查詢 23 |
| 停牌期間沒有股數變動紀錄 | 查詢 27 |
| 資料庫用量超過 Neon 免費額度的 80% | 查詢 20 |

回測與參考價位的獨立驗算（查詢 15、24～26）較耗時，且只在修改計算程式時才可能出錯，不放進每日檢查，修改後手動執行。

## 技術指標

每次執行在寫入日 K 後，會從資料庫讀回該股票全部日 K，計算指標並寫入 `stock_indicators`（與 `stock_prices` 一對一，外鍵 `ON DELETE CASCADE`）。

| 欄位 | 指標 | 計算方式 |
|---|---|---|
| `ma5` `ma10` `ma20` `ma60` | 移動平均 | TA-Lib `SMA`，以交易日計算 |
| `macd_dif` `macd_signal` `macd_osc` | MACD（12, 26, 9） | TA-Lib `MACD`；台股名稱 DIF / MACD / OSC |
| `rsi6` `rsi12` | RSI | TA-Lib `RSI`（Wilder 平滑） |
| `kd_k` `kd_d` | KD（9, 3, 3） | 自行實作台股公式（1/3 平滑、起始值 50），TA-Lib 的 STOCH 與台股不同 |

MACD、RSI、KD 前 120 筆（2015 年下半年）為暖身期，存為 NULL。指標每次都以資料庫中的全部日 K 計算，與每次從 Yahoo 抓多少無關。

## 策略掃描

計算指標後，依每個交易日的收盤價與指標判斷策略，結果寫入 `strategy_signals`（只存符合的組合，每次執行與計算結果同步：新增缺少的、刪除不再成立的）。

| 代碼 | 名稱 | 成立條件（「前一日」為前一個交易日） |
|---|---|---|
| `ma_bullish` | 均線多頭排列 | MA5 > MA10 > MA20 > MA60 |
| `golden_cross` | MACD 黃金交叉 | 前一日 DIF ≤ MACD，當日 DIF > MACD（只在交叉當天成立） |
| `break_ma20` | 突破 20 日均線 | 前一日收盤 ≤ MA20，當日收盤 > MA20（只在突破當天成立） |
| `high_120` | 創 120 日新高（波段） | 收盤價高於前 120 個交易日的最高收盤價（創新高的每一天都成立） |
| `ma20_cross_ma60` | 月線穿越季線（波段） | 前一日 MA20 ≤ MA60，當日 MA20 > MA60（只在穿越當天成立） |
| `golden_cross_trend` | 季線上揚時 MACD 黃金交叉（波段） | MACD 黃金交叉當天，收盤 > MA60，且 MA60 高於 20 個交易日前（趨勢濾網 + 進場觸發） |

標示「波段」的策略（`strategies.SWING_STRATEGIES`）只搭配波段出場規則回測。

執行結束時 log 會列出市場最新交易日各策略符合的股票。

## 策略回測

```bash
python -m scraper.backtest     # 依資料庫中的歷史訊號重新計算（每日 scraper.main 結束時也會自動執行）
```

依 `strategy_signals` 的歷史訊號模擬進出場，結果寫入 `backtest_trades`（每筆交易）與 `backtest_stats`（統計），
規則固定、不做參數最佳化：

| 項目 | 規則 |
|---|---|
| 進場 | 訊號日的下一個交易日開盤價；開盤已接近漲停（+9.5% 以上，除息日以扣除股利後的參考價計算）視為買不到 |
| 出場（短線組） | 持有 5 / 10 / 20 個交易日（含進場日）於收盤賣出；移動停利（進場後最高收盤 − 3 × ATR(14)，收盤跌破則隔日開盤賣出，最長 60 日） |
| 出場（波段組） | 跌破季線：收盤 < MA60 則隔日開盤賣出；移動停利不設最長天數。原本 3 個策略與 3 個波段策略都回測，共 12 組 |
| 重複訊號 | 同一股票、策略、出場規則同時只持有一筆；均線多頭排列只在進入多頭的第一天算訊號 |
| 成本 | 買賣手續費各 0.1425%（不打折）、賣出證交稅股票 0.3% / ETF 0.1% |
| 股利 | 除息日在（進場日, 出場日]的現金股利計入報酬 |
| 期間 | 指標暖身完成後（約 2015-11）到最新一天 |

統計包含交易次數、勝率與 95% 信賴區間（Wilson）、平均 / 中位數報酬、盈虧比、獲利因子、最大虧損、最大連續虧損次數、平均持有天數，
並與兩個基準比較：**任意一個交易日都依相同規則進場**的平均結果（判斷訊號有沒有加分），以及同期間**買進持有**的報酬。

**有沒有優勢**：超額報酬 = 每筆交易報酬 − **同一檔股票**任意日進場的平均報酬。`has_edge` 需同時符合：

1. 超額報酬的 95% 信賴區間**下限大於 0**。區間**依進場月份分群**計算（群集穩健標準誤，自由度 = 月份數 − 1，`excess_clusters` 為月份數）：
   同一個月進場的交易常一起漲跌，不能當成獨立樣本。58 檔合併時，分群後的區間約為原本（視為獨立）的 1.9 倍寬
2. **穩健性**：回測期間以交易日中點（`split_date`）切成前後兩段，兩段的超額報酬（各自與同一段的任意日進場比較）**都大於 0**

這只是最低門檻：短線、波段各同時比較 12 組，純粹靠運氣也可能有組別通過。
**個別股票的結果更要小心**：58 檔 × 24 組共約 1,400 次比較，即使全部沒有優勢，也會有幾組剛好通過
（2026-10-30 有 4 組個股通過，例如國巨＋創 120 日新高只有 11 筆交易，應視為巧合）。

**跌破季線出場的基準分層**：任意日進場若當天已在季線之下，隔天就會被迫出場（白付一次成本），把基準拉低；
多頭排列、創新高等訊號出現時幾乎都在季線之上，天生避開這種情況，不分層會出現假的優勢
（實測：不分層時「多頭排列」「創 120 日新高」搭配跌破季線出場都被判為有優勢，分層後都不成立）。
因此每筆交易只和同一檔股票、訊號日同樣在季線之上（或之下）的任意日進場比較（`Trade.stratum`）。

**資金曲線**（波段評估用）：每個（策略, 股票, 出場規則）以 1 元起算，持有期間依收盤逐日計值、空手時不變，
算出累積報酬 `total_return`、年化報酬 `cagr`、最大回撤 `max_drawdown`、在場時間 `exposure`，並與同期買進持有
（`bh_cagr`、`bh_max_drawdown`）比較。合併範圍為各股票等額資金（不再平衡）的合併曲線。
波段策略常常空手，在大多頭期間總報酬幾乎一定輸給買進持有，價值主要在降低回撤，因此要一起看。

回測統計的範圍：個別股票、全部合併（`ALL`），以及各組別（`TW50`、`CUSTOM`）。比較兩組的結果，可以判斷結論是否只是選股造成的。

已知限制：假設一定能以開盤 / 收盤價成交（未考慮跌停賣不掉、滑價）；觀察名單是現在的大型股與自選題材股（倖存者偏差，結果偏樂觀）；yfinance 少數交易日缺漏（查詢 8）；
鴻海 2018 年減資退還的股款未計入（查詢 23）。

## 投資組合回測

```bash
python -m scraper.portfolio    # 依資料庫中的訊號重新計算（每日 scraper.main 在個別回測之後也會自動執行，約 1 分鐘）
```

個別回測是「每檔股票各一份資金」，持股時間短的策略大部分資金閒置，低估了實際可用的報酬。
投資組合回測用**一筆共用資金**，在整個範圍（全部 / 0050 成分股 / 自選）中依訊號輪流進出場，結果寫入 `portfolio_stats`：

| 項目 | 規則（事先固定，不最佳化） |
|---|---|
| 持股數 | 最多同時 10 檔（`SLOTS`）；每次進場分配前一日收盤總資金的 1/10，現金不足時以剩餘現金為限 |
| 進出場 | 與個別回測的 `simulate` 完全相同；同一檔持有中不重複進場、當天賣出不當天買回 |
| 資金運用 | 開盤賣出（移動停利、跌破季線）的資金當天開盤可再進場；收盤賣出的隔天才能用 |
| 訊號多於空位 | 隨機決定順序，10 個固定亂數種子各算一次，取年化報酬中位數那一次，並記錄年化報酬的範圍 |
| 零股 | 假設可依金額買進（不受一張 1,000 股限制） |

指標：年化報酬、最大回撤、Calmar（年化 ÷ |最大回撤|）、Sharpe、平均持股比例；基準為**同一批股票等額買進持有**（同樣有倖存者偏差）與 0050 ETF 買進持有（參考）。
**風險調整後較佳**（`beats_bh`，判定標準 2）：整段與前後兩段的 Calmar 都高於同一批股票的買進持有。
**有效策略**＝標準 1（個別回測的 `has_edge`，訊號時機勝過任意日進場）與標準 2 都通過。

單一股票 × 單檔資金時，投資組合的資金曲線與個別回測的資金曲線完全相同（`tests/test_portfolio.py`），兩者計算一致。

## 交易計畫（往後實測）

```bash
python -m scraper.paper        # 處理上次之後的交易日（每日 scraper.main 在投資組合回測之後也會自動執行）
```

觀察中策略（`paper.PAPER_STRATEGIES`，目前為「創 120 日新高＋移動停利（不設上限）」）各有一個模擬帳戶，起始資金 100 萬，
規則與投資組合回測完全相同（最多 10 檔、共用資金、成本、股利）。每個交易日收盤後依序：

1. 開盤賣出前一天計畫要賣的股票（跌破移動停利線或季線）；停牌或缺資料則等該股下一個交易日
2. 依隨機順序買進前一天計畫要買的股票；沒有空位、開盤近漲停則略過並記錄原因
3. 除息日股利入帳 → 4. 收盤賣出（持有期滿）→ 5. 記錄當天資金
6. 收盤跌破停利線的持股 → 產生明天開盤賣出計畫；當天出現訊號的股票 → 產生明天開盤買進計畫（含放棄價、ATR 停損參考）

資料表：`paper_accounts`（帳戶、啟用日、已處理到哪天）、`paper_positions`（部位）、`paper_equity`（每日資金，以及同一批股票自啟用日收盤等額買進持有、0050 ETF 的價值作為基準）、`trade_plans`（每天的計畫與執行結果）。
**每個交易日只處理一次，處理過的日子不會重算**，所以紀錄不會事後修改；電腦關機漏掉的日子，下次依序補上（每天只用當天以前的資料）。
2026-11-02 啟用。

驗證：逐日引擎與投資組合回測分開實作，用 58 檔 2015 年起的資料、空位足夠（不搶位子）時比對，5 種出場規則的交易數與每日資金完全一致；
每天寫入資料庫再讀回狀態繼續執行，結果與不經資料庫的執行一致（差異 < 0.01 元，為價格存到小數 4 位的進位）。

## 參考價位

```bash
python -m scraper.levels       # 依資料庫最新的日 K 計算（每日 scraper.main 結束時也會自動執行）
```

每天收盤後，以最新交易日的資料計算**下一個交易日**可參考的價位，寫入 `reference_levels`（每檔每天一筆，保留歷史）。
都是公式計算，不預測漲跌：

| 價位 | 計算方式 |
|---|---|
| ATR 停損 | 收盤價 − 3 × ATR(14)；與回測「移動停利」進場當天的停利線相同 |
| 黃金分割 | 最近 60 個交易日的最高價與最低價：低點在前（上漲波段）取回檔 38.2% / 50% / 61.8%，高點在前（下跌波段）取反彈位置 |
| 漲跌停價 | 下一個交易日參考價 ±10%，依升降單位取整（漲停向下、跌停向上）；ETF 使用 ETF 的升降單位 |
| 參考價 | 平常為收盤價；預告的除息日就是下一個週間日時扣除現金股利；除權（配股、現增）不自行計算，標示 `reference_exact = false` |
| 除權息 | 官方預告（`official_corporate_actions`）中最新交易日之後最近的一筆 |

漲跌停公式已用證交所官方日成交資料驗證：2026-10-29、10-30 全部上市股票與 ETF 共 2,636 筆，最高 / 最低價都沒有超出計算出的漲跌停價，
48 筆剛好觸及漲跌停。已知限制：「下一個交易日」以週一至週五判斷（不知道國定假日）；國外成分 ETF 沒有漲跌幅限制，仍以 10% 計算。

## 使用者資料表（庫存管理）

`app_users`（使用者，email 唯一）、`user_identities`（登入方式：目前為 Google，日後可加自設密碼；同一使用者可有多種）、
`holdings`（使用者自行填寫的庫存，一筆為一次買進）。

這三張表**只由本服務建立**（`init_schema`，每次執行 `scraper.main` 時檢查），資料列由 Java API 依登入者寫入；
本服務只讀取 `holdings` 的股票代號（每日更新庫存中的股票），不讀取其他內容、不修改。

`spring_session` / `spring_session_attributes`：Java 的登入狀態（Spring Session JDBC），主機重新啟動或部署後不會被登出。
結構與 spring-session-jdbc 官方的 `schema-postgresql.sql` 完全相同（2026-11-03 以 `pg_dump` 比對），同樣只由本服務建立。
資料庫層的檢查：價格與股數大於 0、手續費不為負、手續費方式只能是 `actual` / `standard` / `discount`、
折數只在 `discount` 時填寫且介於 0～1、股票代號必須在 `stocks`；刪除使用者時一併刪除其登入方式與庫存。

## 官方開放資料每日累積

```bash
python -m scraper.official
```

每天取得證交所（上市）與櫃買中心（上櫃）全部股票與 ETF 的資料，原樣存入資料庫（與 yfinance 的 `stock_prices` 分開，互不影響），並另存 CSV 備份。

| 來源 | 網址 | 寫入 |
|---|---|---|
| 證交所 日成交 CSV | `twse.com.tw/exchangeReport/STOCK_DAY_ALL?response=open_data` | `official_daily_quotes`（收盤後當日更新） |
| 證交所 日成交 OpenAPI | `openapi.twse.com.tw/v1/exchangeReport/STOCK_DAY_ALL` | 同上（可能比 CSV 晚一天，兩者都抓可互相補漏） |
| 櫃買中心 日成交 OpenAPI | `tpex.org.tw/openapi/v1/tpex_mainboard_daily_close_quotes` | 同上（另提供官方次一交易日參考價） |
| 證交所 除權除息預告 | `openapi.twse.com.tw/v1/exchangeReport/TWT48U_ALL` | `official_corporate_actions` |
| 櫃買中心 除權除息預告 | `tpex.org.tw/openapi/v1/tpex_exright_prepost` | 同上 |

- **授權**：政府資料開放授權條款－第 1 版（https://data.gov.tw/license），可商業使用與散布；對外顯示時須依條款格式標示來源
- **只提供當下的資料**：每天都要執行，漏掉的日子無法補回；休市日執行會取得前一交易日資料（未變動）
- 只保留股票與 ETF（代號 4 碼，或 `00` 開頭），排除權證與特別股
- 下載時連線中斷、逾時或伺服器暫時錯誤會自動重試（最多 3 次，間隔 5、10 秒）；單一來源失敗不影響其他來源
- 不做除權息 / 分割調整，原始數值完整保存，日後可重新計算
- **證交所在除權息日的「漲跌價差」填 0**，不能用「收盤 − 漲跌」推算當日參考價。事件日改以「漲跌價差 ≠ 收盤 − 前日收盤」偵測，事件類型與現金股利由除權除息預告表判斷（`sql/verify.sql` 查詢 17）
- 官方成交量與 yfinance 不同（涵蓋的交易類型不同），收盤價則一致（查詢 18）

**CSV 備份**：每個來源每天一個 `<來源>/<年>/<日期>.csv.gz`，保留官方原始欄位，可直接用 Excel 開啟或重新匯入。
存放位置為環境變數 `ARCHIVE_DIR`，未設定時為 `archive/`（不會 commit）。內容相同時不改寫檔案。

**空間監控**：每次執行最後顯示資料庫用量；超過上限（預設 1024 MB，可用 `DB_STORAGE_LIMIT_MB` 調整）的 80% 時發出警告。

### 雲端每日排程（GitHub Actions）

GitHub Actions 每天自動執行，不依賴這台電腦開機。設定檔與說明在 [`deploy/data-archive-repo/`](deploy/data-archive-repo/README.md)，
要複製到另一個**私人 repo** 使用：

| 設定檔 | 執行 | 時間（台灣） |
|---|---|---|
| `official-daily.yml` | `scraper.official`（官方資料累積，漏抓就無法補回）＋備份檔 commit | 週二到週六 08:17、11:47（備援） |
| `market-daily.yml` | `scraper.main`（觀察名單與庫存中的股票）＋`scraper.health`（資料健康檢查） | 週一到週五 15:40、18:10（備援） |


- 公開 repo 的 Actions 執行紀錄任何人都看得到，紀錄中會出現資料庫主機等資訊；CSV 備份也不宜公開散布
- 私人 repo 取出這個公開 repo 的程式碼執行，資料庫連線資訊放在私人 repo 的 Secrets，CSV 備份 commit 回私人 repo
- 官方資料在隔天早上抓前一個交易日：實測櫃買中心約晚上 11 點半、證交所 OpenAPI 約隔天清晨 5 點才更新，
  證交所 CSV 則在隔天下午 2 點左右換成下一天
- `market-daily.yml` 取代 Mac 的每日排程：先與 Mac 並行一週（時間錯開 40 分鐘），確認 Yahoo 不會擋 GitHub 的連線後，
  執行 `./scripts/install_schedule.sh uninstall` 停用 Mac 排程；一鍵更新仍可隨時手動使用。
  同一天重複執行不會重複交易（交易計畫只處理「上次處理日之後」的交易日；兩邊剛好同時寫入同一天時，後寫入的會因唯一鍵失敗並還原）
- 失敗或資料健康檢查發現異常時 GitHub 會寄信通知，可在 Actions 頁面按「Run workflow」重跑，或在本機點一鍵更新補抓

## 手動一鍵更新

在 Finder 點兩下 `scripts/update-stock-data.command`：開啟終端機視窗顯示進度，結束後顯示成功或失敗，按任意鍵關閉。
等同於在終端機執行 `./scripts/run_daily.sh`，依序執行 `scraper.main`（觀察名單與庫存中的股票）、`scraper.official`（官方資料累積）與 `scraper.health`（資料健康檢查），
前兩者互相獨立。輸出同時附加到 `logs/daily-YYYY-MM.log`。

建立桌面捷徑（只需做一次）：

```bash
ln -s "$(pwd)/scripts/update-stock-data.command" ~/Desktop/更新股票資料.command
```

- 只能在這台電腦、你的帳號下執行：需要 `.env` 的資料庫連線資訊；網站（Vue / Java）沒有任何觸發入口
- `.env` 應設為只有自己能讀（`chmod 600 .env`），權限過寬時程式會提醒
- 同時只會有一個更新在執行（連點兩次，或與自動排程同時觸發時，後來的會直接結束）
- 休市日（國定假日、颱風假）執行不會出錯，結果維持前一個交易日
- 只會對最近 20 個交易日內的缺漏發出警告；更早的已知 yfinance 缺漏列在 `sql/verify.sql` 查詢 8

## 每日自動排程（macOS launchd）

```bash
./scripts/install_schedule.sh             # 安裝（或更新設定）：週一至週五 15:00 自動執行
./scripts/install_schedule.sh status      # 是否已安裝、上次執行結果、最近的紀錄
./scripts/install_schedule.sh run         # 立即在背景執行一次（測試用）
./scripts/install_schedule.sh uninstall   # 移除排程
```

- 執行內容與一鍵更新相同（`run_daily.sh`），結束後以 macOS 通知顯示結果；一鍵更新仍可隨時使用，兩者不會同時執行
- 排定時間若電腦在**睡眠**中，喚醒後補執行一次，並先等網路連線（最多 60 秒）
- **關機或登出**時不會執行，開機後也不補執行：觀察名單每次從資料庫最新的日期接著抓，下次執行就會補齊；
  官方開放資料則由 GitHub Actions 每天累積（見上方「雲端每日排程」），不受影響
- 只在目前使用者的帳號下執行，不需要 sudo；設定檔在 `~/Library/LaunchAgents/com.stocktracker.daily-scraper.plist`
- 執行中途關機或被強制結束時留下的執行鎖，下次執行會自動清除
